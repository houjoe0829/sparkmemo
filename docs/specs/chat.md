# Memo 对话

## 目标与范围

以某一条 memo 为话题跟 AI 对话，入口是 memo 右键菜单的「聊聊这条」，对话开在侧栏新增的「对话」Tab 里。

**包含：**
- 右键菜单入口、对话 Tab、会话列表与单个会话视图
- 调用本机 `claude` 命令行的运行层、流式输出
- 会话持久化、memo 附件随消息发送、模型切换、上下文用量显示

**不包含：**
- 云端 API 直连（不存 API Key，鉴权完全交给已登录的命令行）
- 让 AI 读写 vault 文件（全程零工具权限）
- 手机端支持（依赖子进程，移动端没有这个能力）

## 用户可感知行为

- 功能**默认关闭**。设置 → 对话 → 打开「启用对话」后，Tab 栏才出现对话图标，右键菜单才出现「聊聊这条」。关闭后两个入口都消失，若当时正停在对话 Tab 会自动退回记录 Tab。
- 右击任意 memo 选「聊聊这条」，跳到对话 Tab 并新开一个会话。memo 显示为顶部的引用卡片，光标落在输入框，**不自动发送**。
- memo 自带的图片显示在引用卡片里，随第一条消息一起发给 AI，之后不再重复发送。
- 引用卡片跟随对话一起滚动，滚过之后吸顶并收成一行（隐藏缩略图、压紧内边距），滚回顶部恢复完整形态。
- 模型名在界面上首字母大写显示（Sonnet / Opus / Haiku），存储与传给命令行的值仍为小写。
- 输入框是一个圆角卡片：附件缩略图在上、输入区居中、工具栏在下（模型切换、添加图片、上下文用量、发送键）。支持直接粘贴截图。
- 回复逐字流式显示。发送键在流式过程中变为停止键。
- 对话 Tab 默认展示会话列表，按最近更新排序。点进去聊，左上角箭头返回。悬停行右侧出现删除按钮，右键菜单里也有一份。
- 模型选择**按会话独立保存**；设置里的模型只作为新会话的默认值。
- AI 可以使用工具（读写文件、执行命令、联网、调用 MCP），调用过程以折叠行的形式出现在回复里，点开能看到命令与前 20 行输出。
- 权限模式同样**按会话独立保存**，在工具栏切换，设置里的值只作为新会话的默认值。「不加限制」时按钮显示为红色。

## 实现要点

- **运行层**（[chat-runtime.ts](../../src/chat-runtime.ts)）：`spawn` 本机 `claude`，stdout 是 NDJSON，逐行解析后转成统一的 `ChatChunk` 流。
- **完整能力**：对话跑在用户自己的 Claude Code 配置上，全部内置工具、MCP 服务器、skills、CLAUDE.md 都载入。代价很大，实测单轮 21.8 万输入 token、约 1.28 美元；关掉「加载你的 Claude Code 配置」后约 1 万。这个开关在设置里，说明文案写明了两个量级。
- **两个易错的标志**：`--setting-sources` 显式传值而不是省略，因为它在无头模式下的默认值在 2.x 里变过，显式传值可防止 CLI 升级悄悄改变行为；`--append-system-prompt` 而不是 `--system-prompt`，后者是整个替换，而工具怎么用的规矩（何时用 Grep 而不是 Bash 里的 grep、Read 要绝对路径、不许猜文件内容）都写在默认提示词里，替换掉就等于给了模型工具却没给说明书。
- **工具调用的数据流**：文本走 `stream_event` 的 `content_block_delta` 增量；工具调用只出现在组装好的 `assistant` 事件里，解析时**只取 `tool_use` 块、绝不碰文本块**，否则文本会渲染两遍；工具结果作为 `user` 事件回来，靠 `tool_result` 类型过滤，因为 resume 时 CLI 也用这个事件类型回放用户自己的消息。顶层的 `tool_use_result` 结构化字段暂时忽略，它对 Read 会带上整个文件内容。
- **消息走 stdin**：统一用 `--input-format stream-json`，把消息作为 JSON 写进 stdin。这是附带图片的唯一途径，且让纯文本与带图两条路径不至于分叉。
- **会话续接**：首轮传 `--session-id <uuid>`，之后传 `--resume`，上下文由命令行自己维护，插件不重复发历史。
- **持久化**（[chat-store.ts](../../src/chat-store.ts)）：一个会话一个 JSON，存在 vault 的 `.spark-memo/chats/`。刻意不依赖 Obsidian（同 `stats.ts` / `map-view.ts` 的路子），调用方传入满足 `ChatStorageAdapter` 的对象即可，Obsidian 的 `vault.adapter` 天然符合。
- **发出第一条消息才建档**：只开不聊的会话不落盘、不进列表，避免「0 条消息」的空记录。
- **流式渲染节流**（[chat-pane.ts](../../src/chat-pane.ts)）：用 `requestAnimationFrame` 把多个 token 合并成一帧再渲染。不做这个的话每来一个 token 就重新解析一次，长回复会把界面卡死。
- **回复是有序块列表而不是一个字符串**：文本走增量流、工具调用走组装事件，两者交错到达，单字符串记不住谁先谁后。每帧只重解析「正在打字的那个文本块」，一旦出现工具调用，它前面那块就冻结不再重解析，所以工具用得越多反而越省，纯文本回合退化成和以前一样。
- **工具输出一律用 `setText`**，绝不走 `MarkdownRenderer`。工具结果是文件内容或命令输出，当 markdown 解析会让它往对话里注入标题和链接。取文件名用 `.split('/').pop()` 而不是 `require('path')`，理由见手机端一节。
- **存储的双向兼容**：`ChatMessage` 新增可选的 `blocks`，`content` 保持字符串且**始终是 blocks 的可读拍平**。这个不变式是兼容性的全部依据：旧文件没有 `blocks`，按纯文本渲染；旧版本插件读新文件时 `typeof content === 'string'` 的校验照样通过，会话不会被丢弃，只退化成纯文本。所以 `content` 绝不能改成可选。`parseBlocks` 按块粒度宽容，坏一块只丢那一块。落盘时单条工具结果截断到 4KB，且只截磁盘副本，内存里保持完整。

## 权限模型

无头模式下命令行**不会在用工具前停下来问**，实测 `permission_denials` 为空、没有 `control_request`、不会挂起。也就是说这里没有逐次确认这回事，只能事先定好边界。

提供三档，对应 CLI 的 `--permission-mode`：

| 界面 | 值 | 含义 |
|---|---|---|
| 只读 | `plan` | 能读能搜能联网，不能改文件、不能执行命令。实测请求写文件会被拒且文件不会被创建。 |
| 可以改库里的文件 | `acceptEdits` | 默认值。 |
| 不加限制 | `bypassPermissions` | 工具栏按钮显示为红色。 |

CLI 还有 `auto` / `manual` / `dontAsk`，没有提供：它们的区别只在于**怎么问**，而无头模式根本不问，提供出来会让人以为存在一个不存在的确认步骤。

另需注意：打开「加载你的 Claude Code 配置」后，用户自己的权限规则也会一并载入，可能放宽这里选的模式。

## 手机端安全约束

这是最容易翻车的地方：Obsidian 手机版没有 `child_process`，**只要它出现在模块顶层，插件在手机上会直接加载失败**——不是对话不能用，是整个 Spark Memo 打不开。

三道防线：
1. `chat-runtime.ts` 里 Node 模块一律用函数体内的 `require()`，不用顶层 `import`。
2. `scripts/build.js` 把 `fs` / `os` / `path` / `child_process` 列入 `external`，让 esbuild 原样保留这些 `require`，不要打包也不要提升。
3. capture-view 通过动态 `import()` 加载运行层，且所有入口都过 `Platform.isDesktopApp` 判断。

改动这块之后务必检查打包产物：`require` 必须都在函数体内，`init_chat_runtime` 必须是懒调用的。

## 已知约束与遗留

- **依赖本机 Claude Code**：没装或没登录就用不了。命令行路径可在设置里手填，留空则按 `~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin` 等常见位置探测。
- **会话可能过期**：命令行侧的会话记录有自己的过期策略，太久之后 `--resume` 会失败，目前表现为该轮报错。**尚未做兜底**（预期做法：检测到失效就开新会话并把已有对话内容重新喂进去）。
- **只发图片**：录音等其它附件不随消息发送。HEIC、SVG 等接口不接受的格式会被跳过。
- **单条消息图片总量上限 12 MB**，超出的部分被丢弃并提示。
- **上下文用量是上一轮的结果**：数字来自每轮结束时命令行返回的真实用量，所以本轮发送前显示的是上一轮的值。
- **没有逐次授权**：见上面的权限模型一节。要做到 MyClaudian 那样的逐次确认，需要实现 `control_request` / `can_use_tool` 控制协议，那是官方 SDK 提供的能力，本插件自己 spawn 二进制、自己解析流，没有这套东西。
- **工具行只显示前 20 行输出**，且不做按工具类型的精细渲染（Edit / Write 的 diff 统计、TodoWrite 面板、网页抓取卡片都没做）。

## 引用卡片折叠的边界处理

折叠会缩短可滚动内容的高度，这制造了一个自我推翻的循环：内容刚好够滚一点点 → 折叠 → 内容变矮 → 不够滚了 → 浏览器把 scrollTop 钳回 0 → 判定该展开 → 又够滚了 → 再折叠。每帧翻一次，表现为抖得很快的闪烁。

两道防护：
1. **余量判断**：折叠最多让内容矮一个卡片高度，所以只有可滚动余量大于「卡片展开高度」时才允许折叠。这保证折叠后仍滚得动，位置不会被钳回。余量不够的就一直保持展开——那点内容本来也没多少可滚的，省不出意义。
2. **不对称阈值**：滚过 12px 折叠，回到 4px 以内才展开。中间的缓冲区挡掉橡皮筋回弹和取整误差造成的边界抖动。

另外，流式输出和新消息会改变内容高度，这些时刻也要重算一遍，否则回答变长之后本该允许折叠了却还锁着。

DOM 上引用卡片与消息列表是滚动区里的两个平行容器——重绘消息会清空整个列表，卡片放进去会被一起抹掉。

## 相关坑

`.jp-tab-btn` 带 `display: inline-flex !important`，Obsidian 的 `hide()` 写的是行内 `display: none`，**行内样式打不过 `!important`**——DOM 属性设上了但画面照旧。凡是被 `!important` 修饰过的元素，显隐都要靠同样带 `!important` 的类名（这里是 `.jp-tab-btn.is-hidden`）。
