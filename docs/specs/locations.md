# 地点聚合

## 目标与范围

把所有带 `[名称](geo:lat,lon)` 标签的条目按位置组织，让用户能翻看「我在某个地方写过哪些 memo」。侧栏「地点」Tab 下有两个视图：默认的地图视图，以及按城市分组的列表视图。新获取的地名通过 OpenStreetMap Nominatim 逆地理编码得到，只显示区县或当地对应的行政区名称，不拼接上级城市。

**包含：**
- `geo:` 标签的识别与提取
- 逆地理编码调用与缓存
- 侧栏「地点」Tab 的地图视图与城市分组列表

**不包含：**
- 图片 EXIF 里的 GPS 提取本身（见 [capture-image.md](capture-image.md)）
- 缩放、平移、轨迹线、在线瓦片（明确不做，见下）

## 用户可感知行为
- 地点列表没有记录时，从 8 条空状态提示中随机选择一条，按当前插件语言显示；地图空状态沿用原有翻译，不改变地点数据或发起额外查询。
- 切到「地点」Tab，默认看到一张世界地图，所有带坐标的条目按屏幕距离聚成圆点，圆点大小表示条数。
- 鼠标悬浮圆点时放大并显示具体条数；点击圆点进入该聚合点下的 memo 列表。
- 地图纵向固定、不可缩放，横向可以左右无限循环滚动；初始位置按本机时区推算。
- 顶部右侧可切到列表视图，即原来的按城市分组列表，每个城市下列出该城市写过的所有条目。
- 照片信息确认、移动端定位和手动重试只获取插件当前语言的地名。简体中文、繁体中文、英文、日语界面分别请求 `zh-CN`、`zh-Hant`、`en`、`ja`，不额外请求另一种语言；接口缺少译名时保留它返回的名称。
- 缓存按完整坐标和语言区分，命中后不联网。旧记录继续使用正文原有名称，打开时间线或地点 Tab 不自动补查，也不因切换语言批量改写笔记。
- 网络不可用、查询超时或查不到区县时，保留原始坐标，沿用已有的坐标或占位显示。区县粒度只影响地名，不改成区县中心坐标。
- 从地图或列表点进 memo 列表后，点时间戳跳转到对应 daily note 的原文行；返回按钮回到进来时的那个视图，地图会恢复原来的横向滚动位置。

## 实现要点

- **标签识别**：正则匹配条目文本里的 `[label](geo:lat,lon)`，抽出 `lat` / `lon`。
- 逆地理编码：[geocode.ts](../../src/geocode.ts) 负责 Obsidian 的语言、请求和存储适配，[geocode-client.ts](../../src/geocode-client.ts) 负责队列、缓存和解析。语言与接口参数统一在 [languages.ts](../../src/languages.ts) 定义，缓存键使用同一套语言代码；原有 `zh`、`en` 缓存继续有效。`reverse` 使用 `format=geocodejson`、`addressdetails=1`、`zoom=10`，每次只带当前语言的 `accept-language`，不请求 `namedetails`。
- 区县取值：中国大陆取标准化地址的 `admin.level6`，包含区、县和县级市，不使用街道、上级城市、省或国家填充。其他地区使用标准化的区县字段或可确认的行政区对象名称，不能识别时只保留坐标，不猜测层级。
- 请求保护：照片信息确认、移动端定位和手动重试共用串行队列，请求开始时间至少间隔 1.2 秒，同坐标同语言的并发调用合并。20 秒未完成就结束界面等待；由于 `requestUrl` 不支持取消，底层请求未结束前不会发起另一个请求，也不会采用迟到的地名。没有自动重试或定时扫描任务。
- 持久缓存：独立保存在插件目录的 `geocode-cache.json`，不写入设置文件或笔记正文。完整坐标不做网格舍入，按语言分开缓存，最多保留 2000 项；查不到区县的结果保留 24 小时，成功结果持续复用。缓存损坏或写入失败时保留内存查询能力，并输出不含敏感内容的诊断。
- 错误分类：`403` 停止联网至少 24 小时；`429`、`503` 暂停至少 60 秒，并尊重更长的 `Retry-After`；网络失败、超时、其他 HTTP 错误或响应格式异常暂停 30 秒。保护状态保存到缓存，重载不会立即重试。冷却结束也不自动发请求，须由新的用户操作触发；已有成功缓存仍可使用。日志只记录错误分类和状态码，不记录完整坐标、URL、响应正文或 Memo。
- 公共服务约束：本机队列不能保证全应用所有用户的流量合计符合限制，不能视为完整的合规保证。继续遵守 [Nominatim 官方使用政策](https://operations.osmfoundation.org/policies/nominatim/)，不通过更换应用标识绕过限制。
- 分组：沿用笔记中已保存的地点名称分组，不自动重新查询历史坐标。
- **渲染**：capture-view 里的地点 Tab 按城市展开条目，点击复用搜索 Tab 的跳转逻辑。地图视图与城市列表共用 `renderEntryList` 做下钻，两条入口只有标题不同。
- **底图**：[land-data.ts](../../src/land-data.ts) 内联一份 Natural Earth 1:50m 陆地轮廓（公有领域），经 Visvalingam 精简后约 159 KB，只画海陆分界不画国界。纯 SVG 渲染，不依赖 Leaflet，零网络请求。
- **投影与聚合**：[map-view.ts](../../src/map-view.ts) 不依赖 Obsidian，负责 Web Mercator 投影（纬度裁到 78N 至 60S）、按屏幕像素距离的单遍贪心聚合（半径 14 像素）、圆点半径换算与时区推算初始经度。
- **循环滚动**：墨卡托在经度方向是周期的，左右各挂一份 `use` 副本，视口滑出中间那份时静默回绕 `scrollLeft`。圆点要各自响应点击，三份都是真实节点。
- **重算时机**：地图缩放由可用高度决定，因此渲染尺寸变化时要重跑一次聚合，加防抖。

## 已知约束与遗留

- 依赖公共 API：新定位和手动重试会受到网络或服务限制，失败时保留坐标。历史记录展示原有地名，不依赖在线补查。
- 设备之间没有统一请求调度，不能靠本机限速控制整个应用的流量；用户增多时需要另行评估服务方案。
- 各国行政区划和地图数据完整度不同，不能保证所有坐标都有可识别的区县；没有可用名称时不退回街道或国家冒充区县。
- **不支持缩放**：这是刻意的取舍，换来的是底图可以完全离线内联。代价是同一尺寸下能分辨的最小地理间隔固定，长三角一带仍会聚成若干个点而非逐个城市。
- **跨 180 度经线的簇会被接缝切开**：底图已处理，聚合尚未处理。当前数据最东只到东经 151 度，碰不到这条线。
- **占位文本**：图片附件写入时 label 是占位（如「位置」），是否回填成真实城市名由 UI 决定，不在此模块自动 rewrite 文件。
