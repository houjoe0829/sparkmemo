# 地点聚合

## 目标与范围

把所有带 `[名称](geo:lat,lon)` 标签的条目按位置组织，让用户能翻看「我在某个地方写过哪些 memo」。侧栏「地点」Tab 下有两个视图：默认的地图视图，以及按城市分组的列表视图。城市名通过 OpenStreetMap Nominatim 逆地理编码得到。

**包含：**
- `geo:` 标签的识别与提取
- 逆地理编码调用与缓存
- 侧栏「地点」Tab 的地图视图与城市分组列表

**不包含：**
- 图片 EXIF 里的 GPS 提取本身（见 [capture-image.md](capture-image.md)）
- 缩放、平移、轨迹线、在线瓦片（明确不做，见下）

## 用户可感知行为

- 切到「地点」Tab，默认看到一张世界地图，所有带坐标的条目按屏幕距离聚成圆点，圆点大小表示条数。
- 鼠标悬浮圆点时放大并显示具体条数；点击圆点进入该聚合点下的 memo 列表。
- 地图纵向固定、不可缩放，横向可以左右无限循环滚动；初始位置按本机时区推算。
- 顶部右侧可切到列表视图，即原来的按城市分组列表，每个城市下列出该城市写过的所有条目。
- 城市名首次出现时会有短暂 loading（在做逆地理编码），后续命中缓存直接显示。
- 网络不可用或坐标查无城市时，退化显示原始坐标或「未知位置」。
- 从地图或列表点进 memo 列表后，点时间戳跳转到对应 daily note 的原文行；返回按钮回到进来时的那个视图，地图会恢复原来的横向滚动位置。

## 实现要点

- **标签识别**：正则匹配条目文本里的 `[label](geo:lat,lon)`，抽出 `lat` / `lon`。
- **逆地理编码**：[geocode.ts](../../src/geocode.ts) 调用 Nominatim 的 `reverse` 接口，返回 `city` / `country` 等字段；实现简单，无第三方依赖。
- **速率限制**：Nominatim 免费额度约 1 req/s；[geocode.ts](../../src/geocode.ts) 内做串行 + 间隔；结果按坐标网格 key 缓存到内存，避免同一位置反复查。
- **分组**：按 `city` 归组，无 city 的用 `country` 或「未知位置」兜底。
- **渲染**：capture-view 里的地点 Tab 按城市展开条目，点击复用搜索 Tab 的跳转逻辑。地图视图与城市列表共用 `renderEntryList` 做下钻，两条入口只有标题不同。
- **底图**：[land-data.ts](../../src/land-data.ts) 内联一份 Natural Earth 1:50m 陆地轮廓（公有领域），经 Visvalingam 精简后约 159 KB，只画海陆分界不画国界。纯 SVG 渲染，不依赖 Leaflet，零网络请求。
- **投影与聚合**：[map-view.ts](../../src/map-view.ts) 不依赖 Obsidian，负责 Web Mercator 投影（纬度裁到 78N 至 60S）、按屏幕像素距离的单遍贪心聚合（半径 14 像素）、圆点半径换算与时区推算初始经度。
- **循环滚动**：墨卡托在经度方向是周期的，左右各挂一份 `use` 副本，视口滑出中间那份时静默回绕 `scrollLeft`。圆点要各自响应点击，三份都是真实节点。
- **重算时机**：地图缩放由可用高度决定，因此渲染尺寸变化时要重跑一次聚合，加防抖。

## 已知约束与遗留

- **依赖公共 API**：Nominatim 是社区服务，网络阻塞或封 IP 时地点 Tab 会大面积显示坐标。可考虑接入其它服务或本地城市库作为兜底。
- **缓存不落地**：Obsidian 重启后缓存清空，重进 Tab 会重新查询；对经常访问的城市影响不大（走缓存），对稀有位置每次都要等。
- **精度粗**：只到城市级，不区分区县；对同城不同地点的旅行不友好。
- **不支持缩放**：这是刻意的取舍，换来的是底图可以完全离线内联。代价是同一尺寸下能分辨的最小地理间隔固定，长三角一带仍会聚成若干个点而非逐个城市。
- **跨 180 度经线的簇会被接缝切开**：底图已处理，聚合尚未处理。当前数据最东只到东经 151 度，碰不到这条线。
- **占位文本**：图片附件写入时 label 是占位（如「位置」），是否回填成真实城市名由 UI 决定，不在此模块自动 rewrite 文件。
